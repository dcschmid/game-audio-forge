This document records the dependency research, the integration decision, and
the license inventory. It is the basis for the (still open) project-license
decision.

## Key finding

**audio.cpp is a superset.** It already natively wraps the models this project
targets, so we do not need separate C++ ports:

- `ace_step` — ACE-Step 1.5 (Base / Turbo / XL) → instrumental music
- `midashenglm_gen` — MiDashengLM-Gen → sound effects / ambience
- `stable_audio` — Stable Audio 3.0 (SFX + Music)
- `controlfoley` — ControlFoley → foley SFX
- `minimax_music3` — MiniMax Music 3 → songs with lyrics

This means **one engine, one build, one model manager** covers both the music
and SFX paths. `acestep.cpp` (a standalone ACE-Step C++ port) is therefore not
needed — audio.cpp's `ace_step` family is the maintained path.

## Integration decision

- **audio.cpp** is the inference foundation. We link against it (C ABI or its
  server API) as a third-party dependency fetched at build time — we do **not**
  copy its source into this repository.
- **Soundbox** is a product-shape reference (UI, profiles, license-before-download,
  MCP surface). It is a Node/Electron app, not a C++ library, so it is not a
  dependency. We borrow its ideas and build our own native layer.
- **ACE-Step-1.5 / MiDashengLM-Gen** Python repos are reference-only. We use
  their **GGUF weights** (downloaded at runtime via the audio.cpp model
  manager), not their Python code.
- **FFmpeg** is a system dependency, dynamically linked (LGPL). We do not
  bundle or statically link GPL components.

## License concept (open decision)

The project is **private** until this review is complete. When choosing the
project license, the constraints are:

1. **Compatibility with Apache-2.0** (audio.cpp) — the project license must
   allow linking against and distributing with an Apache-2.0 dependency.
   Apache-2.0, MIT, BSD and GPL-family all work for *linking*; the choice
   depends on how permissive we want our own code to be.
2. **LGPL (FFmpeg)** — dynamic linking is fine under any of the above; static
   linking or GPL-only FFmpeg components would need review.
3. **Model-weight licenses are separate** and do not constrain the project
   license (we don't redistribute weights), but they constrain *commercial use
   of generated audio* for the conditional models.
4. **Open-source publication** is deferred until (1)–(3) are settled.

**Candidate project licenses** (to decide after review):

- **MIT** — maximally permissive, simplest. Good if we want broad reuse.
- **Apache-2.0** — permissive + patent grant, matches audio.cpp. Good default
  for a C++ project with a permissive dependency.
- **GPL-3.0** — copyleft; would require the whole combined work to be GPL.
  Only if we want strong copyleft.

**Recommendation (pending user decision):** **Apache-2.0** for the project
license — it matches the primary dependency, includes a patent grant, and is
the conventional choice for a permissive C++ toolkit. Confirm before adding a
`LICENSE` file.

## What we will NOT do

- Copy audio.cpp, Soundbox, or any model repo's source into this repository.
- Commit model weights or large audio files.
- Statically link FFmpeg or enable GPL-only components without review.
- Add a `LICENSE` file until the project license is explicitly chosen.
